# Реліз v0.9.0

`v0.9.0` робить алгоритм скринінгу стійким до реальних вхідних даних: інші прилади, відсутні виміри (полярність, m/z) та чисті blank більше не ламають обробку. Паралельно уточнено екранну термінологію, щоб назви метрик відповідали лабораторному словнику.

## Що змінилося для користувача

- **Вхідні формати та профілі приладів**:
  - Приймаються файли **CSV, TSV, TXT, XLSX, XLS**. Текст з роздільниками читається як таблиця; Excel додатково несе кольори заливки клітинок як мітки оператора.
  - Новий **профіль приладу** в панелі імпорту дозволяє підключити прилад з іншими заголовками експорту: він зіставляє заголовки приладу (наприклад `RetentionTime → RT`, `PeakArea → Area`) з канонічними полями і може оголосити `Base Peak` / `Polarity` відсутніми.
  - Набір зразків формується у workspace з одного або кількох файлів.

- **Робота без Polarity або без Polarity та Base Peak (RT-only)**:
  - Без колонки `Polarity` усі рядки утворюють одну групу `n/a` замість розбиття за полярністю.
  - Без `Polarity` і `Base Peak` одночасно алгоритм працює в режимі RT-only — реплікати й blank зіставляються лише за часом утримання.
  - Коли m/z відсутній у всьому наборі, штраф довіри за відсутність m/z не застосовується (це властивість формату даних, а не слабкість зіставлення).

- **Signal-to-Blank без корзини blank**:
  - Якщо у піка зразка немає зіставленої корзини blank, поле більше не лишається порожнім. У `Why.BlankState` повідомляється один із трьох станів: `blank_subtracted` (blank зіставлено й віднято), `blank_clean_here` (blank є, але чистий на цьому RT), `no_blank_loaded` (blank узагалі не завантажено — наприклад, був настільки чистий, що оператор нічого не виявив).
  - Обидва випадки «без blank» лишаються **Real Compound** — чистий blank читається як сильний результат, а не як відсутній.

- **Ширина корзини кластера за поведінкою сурогата**:
  - Відкривши додаткові дані (аудит) сурогата, ви побачите `Why.BinWidthSuggestion` з трьома рекомендаційними метриками розкиду RT — `MaxAbsRtShift`, `KStdevRt` (k·σ, k=3) і `RangeRt` — кожна з кількістю реплікатів.
  - Це лише підказка: жодне значення не застосовується автоматично, оператор вводить його в Конфігурацію аналізатора вручну.

- **Термінологія**:
  - **CV% — це RSD** (відносне стандартне відхилення). UI тепер позначає метрику `RSD (CV%)`, числове значення не змінюється.
  - **1 реплікат = 1 хроматограма** — підпис тепер «Реплікати (хроматограми)».

- **Підсвічування походження реплікатів**:
  - Кількість реплікатів візуально виділена; при наведенні показується походження кожного реплікату — вихідні файли та, якщо кластер зібрано з паралельних зразків, які саме зразки він охоплює (бурштинове кільце позначає змішане походження).

## Що це означає на практиці

- Дані з нового приладу підключаються через профіль колонок без зміни коду.
- Методи без полярності чи без m/z (GC-FID, LC-UV тощо) тепер проходять скринінг.
- Чистий blank більше не виглядає як «немає даних» — він явно позначений і не псує висновок.
- Сурогат сам підказує розумну «ширину корзини» для допуску RT.
- Назви метрик на екрані збігаються з лабораторним словником (RSD, хроматограма).

## Технічні деталі

- Ядро Rust/WASM: `Polarity` опціональна, прапорець `polarity_available`; три стани blank у `Why.BlankState`; метрики `Why.BinWidthSuggestion` для сурогатів.
- TS: профілі зіставлення колонок (`ColumnProfile`, `INSTRUMENT_PROFILES`), авто-визначення `polarity_available`.
- UI/i18n (en/uk/ru): підписи RSD (CV%) та «Реплікати (хроматограми)», підсвічування реплікатів, dropdown профілю приладу.
- Тести: Rust unit (5), WASM/TS vitest (35), Python parity (12) — усі зелені.
